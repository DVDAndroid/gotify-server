# gotify-splitter

Proxy in front of Gotify v2 and v3 (v3 on a cloned DB) so both stay in sync before cutting over.

- every request -> `PRIMARY_URL`, whose response goes back to the client (including the `/stream` websocket)
- writes (POST/PUT/DELETE/PATCH) -> also replayed, in order, to `SECONDARY_URL`; response discarded, errors only logged
- reads (GET/HEAD/OPTIONS) are not mirrored
- cutover: swap the two URLs, later drop the splitter and point caddy at v3

Known limit: tokens generated by the server (new app/client) differ between v2 and v3, since each
backend generates its own. Create them before the clone, or copy them across by hand.

```yaml
  gotify:
    # no caddy label anymore
  gotify3:
    # ...
    labels:
      caddy: http://gotify3.lan   # v3 app connects here directly, bypassing the splitter
      caddy.reverse_proxy: "{{upstreams 80}}"
  splitter:
    build: ./splitter   # or your registry image
    restart: unless-stopped
    environment:
      PRIMARY_URL: http://gotify:80
      SECONDARY_URL: http://gotify3:80
    labels:
      caddy: http://gotify.lan
      caddy.reverse_proxy: "{{upstreams 80}}"
```

Test: `cd splitter && go test ./...`
